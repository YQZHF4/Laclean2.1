3. 点云算法：Open3D，不建议第一阶段上 PCL
PCL 本身很强，但 Python 绑定长期存在版本、编译和 Windows 部署成本高的问题。当前 Open3D 已经安装，而且足以完成第一阶段：
PCD、PLY、XYZ、PTS 等点云读写

Open3D 也具备多边形体积裁剪能力。Open3D 点云裁剪文档
我的建议是：
NumPy
  ├─ 作为点坐标、颜色、法线的标准内部数据
  ├─ 转给 Open3D 执行算法
  └─ 转给 OCC 执行显示
这样以后如果确实需要某个 PCL 特有算法，只需增加一个算法适配器，不必重写界面和数据模型。
4. 点云可视化：可以用 OCC
OCC 有专门的 AIS_PointCloud，支持点云显示、包围盒和点/点子集选择。Open CASCADE AIS_PointCloud 文档
推荐 OCC 做中央统一场景，原因是以后必须同时显示：

STEP 数模
机械臂
工装
坐标系

需要注意：OCC 擅长 CAD 显示，不负责点云滤波算法；框选、套索裁剪等交互也要由我们自己补充。第一版完全可实现，但这是首期较重要的交互开发点。
5. PyOpenGL：当前可以不装
如果 OCC 负责显示，OCC 自己管理 OpenGL，不需要业务代码直接调用 PyOpenGL。除非以后需要自定义 OpenGL 着色器、热力图或特殊点精灵效果，再考虑加入。

五、机械臂 STEP 文件的问题
资料中的 【机械臂R6-093S】客户模型.stp 可以作为“数模”整体导入显示，但它不一定能直接用于机械臂运动。
要让机械臂各关节随角度正确转动，至少需要：
每个连杆可单独访问的模型
六个关节的旋转轴
各关节原点
关节正负方向
零位姿态
关节限位
DH 参数或厂家运动学参数
如果当前 STEP 是单一合并实体，通常需要让同事在 SolidWorks 中按连杆拆分，或者确认 STEP 本身是否保留装配结构。备注内容看起来也是在提醒“先拆分模型，再通过正运动学计算各连杆位置”。
所以“导入数模”和“导入可运动机械臂模型”应当是两个接口：
普通数模：STEP/IGES/STL，作为静态场景对象
机械臂模型：连杆模型 + 关节配置 + 运动学描述
